## Bug report (user, real device, build from Releases): tapping the mic shows «تشخیص گفتار روی این دستگاه در دسترس نیست. متن را تایپ کنید.» The system mic indicator (green dot) appears, so a recognizer started.
## Diagnosis (main agent, from code)
- `SpeechErrorKind.UNAVAILABLE` is produced by BOTH `isRecognitionAvailable == false` AND recognizer errors 12/13 (`ERROR_LANGUAGE_NOT_SUPPORTED/UNAVAILABLE`, AndroidSpeechSource.kt ~L124). On API 31+ the code prefers `createOnDeviceSpeechRecognizer` when `isOnDeviceRecognitionAvailable`; if the on-device fa-IR model is not installed it fails with 12/13 and there is NO fallback to the standard recognizer (`createSpeechRecognizer`, which can use Google's server model). The same message hides very different problems.

## Deliverables
1. Fallback chain inside `AndroidSpeechSource` (or a small wrapper `FallbackSpeechSource`): on-device (API 31+) -> on error 12/13/`ERROR_CLIENT`/service-disconnected, automatically retry ONCE with the default recognizer (`createSpeechRecognizer`, network allowed, no PREFER_OFFLINE) -> if that also fails with NETWORK/SERVER/UNAVAILABLE emit a typed error. Never loop. Release/destroy recognizers correctly between attempts (main thread). Emit a `SpeechEvent.EngineChanged(engine)` (ON_DEVICE / SYSTEM) for diagnostics.
2. Distinct error kinds and Persian messages: NO_RECOGNIZER_INSTALLED (no service at all: tell user to install/enable «Google» app / «Speech Recognition & Synthesis» and how), LANGUAGE_PACK_MISSING (offer download), NETWORK (recognizer needs internet; suggest retry or typing), NO_MATCH, BUSY, NO_PERMISSION. Show a small diagnostic tail in debug-friendly form, e.g. «(کد ۱۳)» appended in a muted style — this helps the next bug report; no stack traces.
3. Language-pack download (API 33+): `SpeechRecognizer.checkRecognitionSupport` for fa-IR; if on-device language is not installed offer a button «دانلود بسته فارسی» calling `triggerModelDownload`; show progress/result (listener `ModelDownloadListener` API 34+, otherwise just trigger and tell the user to retry). Below API 33: link to system voice settings via `Intent("com.android.settings.TTS_SETTINGS")`/`Settings.ACTION_VOICE_INPUT_SETTINGS` (resolve safely, hide button if no handler).
4. A «تشخیص گفتار» diagnostics card in Settings (about section): shows Android API level, `isRecognitionAvailable`, `isOnDeviceRecognitionAvailable`, installed recognition service package names (`PackageManager.queryIntentServices(RecognitionService)` — manifest <queries> already present), fa-IR support result, last voice error kind+code. 5. Tests (CI/Robolectric/JVM): fake recognizer factory drives the chain: on-device error 13 -> fallback to system once -> success; both fail -> typed error; no service -> NO_RECOGNIZER_INSTALLED; never more than 2 attempts; recognizers released each time.
